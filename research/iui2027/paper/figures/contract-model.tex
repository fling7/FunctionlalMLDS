  \caption{The compact FunctionalMLDS contract and its implementation mapping.
  A scenario step reaches a runtime action only through an explicitly provided
  capability use, capability, and binding. Spatial responsibility is resolved
  at the highest matching tier---asset before object group before zone---and
  ambiguity at that tier blocks execution. Stable model identifiers connect the
  Unity selection, backend routing, and structured assertion evidence.}
  \Description{A three-part diagram. Part a shows the executable contract from
  Scenario through ScenarioStep, CapabilityUse, Capability, RuntimeBinding, and
  RuntimeAction, with cardinalities on every edge. Capability owns one or more
  Effects, each specified by one or more Assertions; a ValidationCase checks
  bindings and assertions. A dashed boundary states that ScenarioStep cannot
  directly reference RuntimeAction. Part b shows an asset, its optional object
  group, its zone, and candidate agents. A responsibility resolver evaluates
  asset assignments before group assignments and group assignments before zone
  assignments. Exactly one owner permits routing; multiple owners at the
  highest matching tier are ambiguous and blocked, while no owner or route is
  rejected. Part c maps the contract to the implemented system: a Unity desktop
  component binds a selected collider to a stable model entity, the backend
  validates the pinned model and resolves responsibility and permitted
  handoffs, and runtime evidence records the scenario, capability use, binding,
  provider, target, and assertion verdict.}
